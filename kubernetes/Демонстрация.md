# Сценарий скринкаста (5–7 минут)

Перед записью выполните установку и сборку образов. В кадре не показывайте долгую загрузку .NET/NuGet; начните с готового терминала в папке проекта. На Windows можно использовать PowerShell-скрипты, на macOS/Linux — одноимённые `.sh`-скрипты.

| Время | Что показать | Команда или действие |
|---|---|---|
| 0:00–0:35 | Проект и Dockerfile | Откройте папку `src` и кратко покажите три Dockerfile: API, DbMigrator, Client. |
| 0:35–1:10 | minikube и образы | `minikube status`; затем `minikube image ls` и поиск `taskflow`. Скажите, что образы собраны локально и загружены в кластер. |
| 1:10–1:40 | Применение манифестов | `kubectl apply -k .\kubernetes` — в выводе должны быть namespace, services, deployments, job и configmaps. |
| 1:40–2:20 | Готовность | `kubectl get pods -n taskflow -w`; дождитесь `Running` у PostgreSQL/API/frontend и `Completed` у migrator, затем `Ctrl+C`. Подчеркните, что PostgreSQL — StatefulSet. |
| 2:20–2:45 | Все объекты | `kubectl get all,pvc -n taskflow`. Покажите PVC `data-taskflow-postgres-0`: он создан StatefulSet и сохраняет данные БД. |
| 2:45–3:25 | Масштабирование | `kubectl scale deployment taskflow-api -n taskflow --replicas=3`, затем `kubectl get pods -n taskflow`. Покажите три API Pod. |
| 3:25–5:45 | UI | В отдельном окне: `minikube service taskflow-frontend -n taskflow --url`. Для Docker driver замените в напечатанном адресе `http://` на `https://` и откройте его. Примите предупреждение self-signed сертификата. Зарегистрируйтесь, войдите, создайте Project, Task и Tag; измените статус или удалите Tag. |
| 5:45–6:15 | Итог | Вернитесь в терминал: `kubectl get pods -n taskflow`; все API Pod должны остаться `Running`. Кратко скажите: frontend проксирует `/api` к API, а API хранит состояние в PostgreSQL. |

Не включайте в запись пароли, `.env.compose.local` или содержимое `Secret`. Записывайте окно целиком или область терминал + браузер; длительность держите в диапазоне 5–7 минут.
